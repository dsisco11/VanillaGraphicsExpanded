# Binding admission migration map

Temporary implementation support for [Rendering.BindingAdmission.todo](Rendering.BindingAdmission.todo).
The approved [proposal](Rendering.BindingAdmission.Proposal.md) controls the design. This map records
source findings and implementation traceability; completion status and receipts belong to the plan. Remove it in phase 7
after preserving required decisions and evidence. Paths below are relative to `VanillaGraphicsExpanded/Rendering`
unless prefixed with a project name. File families include their partials; method names identify search anchors.

## Authority and traceability

The new proposal deliberately supersedes the old requirement to prove resource usability at every use.
It does not supersede canonical metadata, original association identity, native outcome policy, explicit
synchronization, or actual allocator/completion ownership. Existing documentation describes current code
until the relevant unit changes it; it must not be used to restore the rejected execution-guard architecture.

legal reentrant lifecycle mutation must wait until the enclosing owner use interval ends. Current guard

withdraw selections before release. U4–U6 still own removal of their existing execution guards.

## Binding caller chain inventoried before replacement

`ShaderContractGenerator/RuntimeBindingCaptureEmitter.cs` emits resource properties and
`CaptureBindingsCore`, retaining CPU selections/copies and captured uniform versions. The current
generator does **not** call `ShaderPreparedSubmission` or emit `ShaderInputValidation` fields.
The older generated-Submit/history description in `Rendering.ShaderBindingState.md` is stale for this
portion; reconcile it in U4, without treating it as a second production path that must be preserved.

`GpuProgram`/`GpuComputeProgram` capture feeds `RHIResourceBindings`, then context binding/graphics/compute
operations; recorded bindings retain that same captured table in list-owned arguments and replay through
the immediate context. Backend `BindResources`, `GraphicsDraws`, `IndexedBatches`, `IndirectGraphics`
and `ComputeDispatch` all call `BeginBindingExecution`. It retains the shader program, obtains the CWT
`OpenGLBindingPlan`, then calls `ValidateResourceBindings` on every execution.

Sampler/image cases validate availability, call `ShaderPreparedSubmission` (which validates it again),
build `ShaderInputValidation` keys via multiple reference metadata accesses, and retain original backing
wrappers. Buffer cases call `ValidateBufferInput` -> `RequireRange`, then read metadata again in
`ValidateAndRetainBuffer`. Publication can read `TextureId`/image selection again. A publication receipt
only suppresses the later native binding work; it does not suppress these earlier checks.

`PublishResourceBindings` calls `BindingReuse.ReuseUniformPublication` on receipt reuse; that still walks
uniform candidates, retains buffers, commits allocator last-use and commits captured CPU state. Those
actions have different purposes and must not be deleted as a block. `OpenGlStateCache.BindingPublication`
currently advances a single global receipt revision for external observations. Replace its broad
invalidation with affected executed-state domains while retaining interruption semantics.
