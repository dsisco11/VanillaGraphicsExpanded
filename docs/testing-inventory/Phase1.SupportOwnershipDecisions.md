# Support ownership and lifetime routing

`Phase1.SupportRouting.csv` assigns all 272 support sources to reviewed responsibilities. `Phase1.SupportGroups.txt` lists the exact members; `Phase1.SupportSources.csv` supplies their current paths and declarations. These are proposed ownership groups for later migration, not new destination directories. The direct-reference counts in `Phase1.SupportOwnership.csv` are search cues only: common type names, partial classes, extension methods, and collection strings make text matches incomplete or misleading.

## Shared execution and fixture owners

- The GPU observation framework owns collection-prepared checker programs; observations, selections and result scopes belong to individual cases. `HeadlessGLFixture` owns the hidden physical context, registered resource namespace and cache-store override. `CleanupGpuResources` drains case work and upload/ring services, while `RetireResourceServices` also retires checker preparations and the manager. `GpuTestCollection` and `NearFieldMaterialCaptureCollection` are collection policies, and the latter serializes singleton material capture.
- `ComponentShaderPrograms` owns its API/platform scopes, prepared program lists and frame-light publication. `RenderTestBase` borrows collection observations and owns case targets, lighting and raw geometry; its returned framebuffer belongs to the caller. `ShaderTestFramework` tracks returned textures and framebuffers. `LumOnShaderFunctionalTestBase` owns case shader programs, cameras, uniforms, lighting and its framework.
- Water and near-field numerical fixtures retain class-scoped executables and grant exclusive case leases. Cases own fresh inputs and scene resources. Near-field lease acquisition checks manager/context affinity; water consumers select the original GPU context before acquisition.
- `TestAssetSnapshot` retains immutable built/captured payloads process-wide and returns validated copies. `CapturedPayload` borrows it. `SlicedShaderAssets` owns case copies. `DiagnosticReports` emits runner output, not physical report files. `CpuStateCollection` serializes global CPU state without owning data.
- `RuntimeLightingHost` owns its passed `WorldProbeModSystem`; `SurfaceCacheRuntimeFixture` borrows its supplied GPU observations even though an existing property comment says “Owns.” `SurfaceLightingConsumerRuntimeFixture` composes this host and relies on idempotent world disposal. `EngineShaderPlatformScope` changes and restores engine globals and native program binding; preserve its serialization and disposal scope.

## Domain and auxiliary ownership

- AO, cloud, near-field, water, terrain, runtime lighting, and lighting/sky scene groups own or borrow resources at their named consumer boundary. Their exact source members are recorded in `Phase1.SupportGroups.txt`. Group placement does not classify every consuming test as integration; typed shaders and authored scenes can form component tests.
- Terrain support has three distinct paths: precompiled SPIR-V numerical wrappers; `TerrainLinkedTestProgram`, which adopts a detached native program for an engine wrapper; and stage assembly/generation support that accepts both authored GLSL compilation and SPIR-V loading. `TestShaderCache` also supports authored GLSL fixtures and a driver-binary store, so it is not exclusively a SPIR-V loader.
- `ShaderBuildFixture` creates case-owned temporary shader trees and removes its root on disposal. `GeneratorFixture` runs the shader-contract generator and retains static source/metadata while generated runtime assemblies remain loaded for the process. `RuntimeCaptureSupport` supplies managed generated-runtime substitutes; it does not own native GPU resources. `GeneratorCompilation` runs the OpenGL generator against authored native-call fixtures and retains temporary PE paths process-wide.
- `CountingDiskCacheFileSystem` and `InMemoryMaterialAtlasFileSystem` are managed filesystem substitutes, not physical persistence witnesses. The former has one-time stream commit/lease release; the latter exposes stored byte arrays on reads and repeated write-stream disposal can repeat commit. `WorldProbeRoomScenario` runs the real CPU trace integrator over authored world data; `ControlledVoxelWorld` supplies authored cells while production tracing still executes.
- `ScopedPbrMaterialFixture` saves and restores the exact singleton derived-array reference and one material entry; its consumers require serialized execution. World-partition providers and trace-geometry fixtures keep controlled completion and publication state per case. The numerical CPU multiple-scattering class fixture is currently dormant because its consuming cases are statically skipped.

## Migration risks and retained observations

- Sequential `Dispose` methods in `ComponentShaderPrograms`, `ShaderTestFramework`, `LumOnShaderFunctionalTestBase`, `RuntimeLightingHost`, `SurfaceCacheRuntimeFixture`, and `SurfaceLightingConsumerRuntimeFixture` can stop after an earlier owner throws. The last fixture can then miss Harmony unpatching. `ProgramAcquisitionCapture` and `NativeShaderAllocationCapture` can similarly fail before patch/capture restoration. `RenderTestBase` raw geometry cleanup checks context validity rather than physical-context identity; callers must restore the owning context.
- `GeneratorCompilation` retains generated PE directories without deletion and can create redundant directories for concurrent same-key value factories. `ExposureTestStorage.Create` and `ComponentAtomicCounters` can leave a native buffer allocated when initialization throws before an owner is returned. These are source-reviewed cleanup findings, not observed failures.
- `CloudStoredVolumeViewScene` owns `CloudOitSurface` through its case resource list and retires it in reverse order. `RasterDepthHierarchyReference` borrows pipelines returned by `PostprocessDraw.Prepare`; `PostprocessDraw` owns and retires the underlying `GraphicsPipelineAsset` values. `ObjectParamsUbo`, `RasterCameraExposureShader`, and `SkipOnCIAttribute` have no active test-source consumer/application in the reviewed symbol search. They remain inventoried as unreferenced support; any removal requires a later decision. These observations are recorded in `Phase1.SupportRouting.csv` without leaving ownership ambiguous.

Support ownership was reviewed by source and representative consumers. This routing does not certify every helper algorithm or numerical reference for assertion independence; the tests that use them retain their own method-level boundary and oracle reviews in the group inventories.
