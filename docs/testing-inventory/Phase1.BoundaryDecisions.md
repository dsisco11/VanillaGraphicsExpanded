# Reviewed test boundaries and migration candidates

This is the source-backed decision record for the behavior-group inventory. The complete method routing is in `Phase1.MigrationRouting.csv`, backed by the five group inventories and `Phase1.DiscoveredCases.jsonl`. The table below highlights classification conventions and mixed cases; it is not an exhaustive duplicate of the method inventory. Proposed owners describe responsibility, not a final directory layout.

## Classification conventions

- Classify the contract and exercised boundary of a method or a verified group of methods. Unit tests isolate a narrow rule; component tests exercise a cohesive subsystem and its internal composition; integration tests verify a real boundary between independently functioning parts; end-to-end tests require a complete representative workflow path.
- Treat purpose and environment separately from level. A numerical shader can be a component under a real GPU environment; native loading, GL state, and ABI interoperability can be integration. `Category=GpuIntegration` is currently a runner-selection trait, not proof of integration level.
- Keep real I/O when the contract is persistence, process lifetime, or native interoperability. An in-memory filesystem substitute does not turn a cohesive cache subsystem into real filesystem integration.
- Preserve current traits, cases, skips, and runner membership until selection changes are decided separately. No inspected test proves a complete deployed game end-to-end workflow.

## Confirmed migration and quality findings

- Separate lookup correctness from diagnostic workload; cache-key rules from persistence; compiler-process lifetime from receipt reuse; and file-based implementation identity from isolated rules. Audit the mixed `PreparedProgramBinary`, profiling, and partition groups at method level.
- Rename or rehome the scheduler `IntegrationSmoke` and voxel `EndToEnd` groups to match their component boundaries. `GPU/ShaderDefineInjectionTests` uses declared variant selection and built SPIR-V rather than source define injection; its names and comments overclaim the mechanism. Headless `GPU/PbrHeightBakeFullChainTests` and `GPU/SurfaceLightingConsumerRuntimeTests` do not establish deployed end-to-end coverage.
- `Unit/GpuVboUnitTests` and `Unit/GpuEboUnitTests` have creation cases that never invoke creation and assert `True(true)`; debug-name cases assert authored strings. `Unit/PBR/Materials/MaterialAtlasCacheWarmupPlannerTests.CountExisting_CountsHits_ByPayloadKind` tests its nested fake's counting implementation, not the production planner. `Profiling/ProfilerEventSourceTests.BeginScope_ReturnsNoop_WhenDisabled` does not establish disabled state or assert a no-op result. Keep these cases in the baseline; they require separate corrective decisions.
- `PbrGlobstarTests.TieBreak_FirstRuleWins_WhenPriorityEqual` implements winner selection inside the test rather than calling production registry selection; retained material-registry tests do exercise tie/order behavior. `Squirrel3NoiseTests.Constants_MatchShaderInclude` checks hardcoded CPU constants without reading the shader include. These names and assertions do not prove their claimed contracts.
- `Unit/LumOn/WorldProbes/WorldProbeCoordinateSpaceTests` calls only a private test helper for two identical authored input/expectation pairs; its camera-bob case does not vary a bob or camera input. `Unit/PBR/Materials/MaterialAtlasParamsSyncAsyncParityTests` compares two synchronous builder orders through a test-owned blit, without invoking an asynchronous service. Record their actual contracts before moving them.
- `ShaderPatchingTests.DictionaryResolver_ResolvesBareImportReference` exercises a test-support resolver, rather than production shader patching. `StateValueLayoutTests.ReportManagedSizes` and `ShaderPatchingTests.Diagnostic_DumpTokens` are observation workloads currently selected as ordinary tests; their purpose/selection requires a later decision.
- `GPU/GpuEboIntegrationTests` upload cases named `UploadsDataCorrectly` assert wrapper count/type/size but do not read back uploaded bytes. Its disposed-upload case accepts any exception, and detached-buffer cleanup follows assertions rather than a `finally`. Its managed debug-name and formatting cases are unit rules within a native suite.
- `GPU/GlStateCacheUnbindIntegrationTests.UnbindMethods_SetBindingsToZero` checks cached binding getters without an independent GL binding query, so a native unbind failure can escape its oracle. Several native cases, including `GBufferExternalFramebufferTests` and a direct-file pipeline case, release raw names or program owners after assertions rather than through failure-safe cleanup.
- `GPU/LiquidDepthShaderProgramTests.ColorAndDepthProgramsLinkSharedWaveBlock` proves both programs link but reads expected block slots from static declarations, not linked native block introspection. `GPU/LumOnDebugShaderDemandTests` has a specialization claim supported only by successful variant admission.
- `GPU/LocalExposureQualificationTests.WarmProductionCost` constructs the global baseline pipeline from one program but submits another program's binding capture for its baseline action. `GPU/BloomRadialDiagnosticsTests.RawHaloStoragePrecisionComparison` records error metrics without a precision threshold; its other diagnostic has only finite/nonnegative and source-retention assertions.
- `EngineGraphicsGeometryTests.ImportedEngineGeometrySubmissionPreservesContract` exercises direct `RHICommandContext` draws using imported engine geometry. The former reentry assertions were inside a mocked `IRenderAPI.RenderMesh` callback that this path never invokes, so they were removed with the unused mock state. No executed draw-time RHI reentry witness remains; treat that as an explicit coverage gap for later test design. The state-switching and framebuffer-routing suites also had empty Harmony owners; those owners and the associated transpiler claims were removed, and their names now describe the bound native call paths they exercise.
- `PbrPoissonMultigridVCycleTests.MultigridVCycle_ThreeLevel_ReducesResidualMore` manually sequences shader kernels rather than invoking the production multigrid orchestrator. Its baseline two-level control mutates buffers reused by the three-level path. An independent control setup failed the existing one-percent superiority assertion for sine and noise inputs; the shader paths use different work budgets, and no documented solver contract guarantees that ordering. Retain baseline execution and selection for the migration, but do not count its passing assertion as independent three-level superiority coverage. Resolve the intended convergence contract and oracle separately.
- `GPU/FramebufferAttachmentNotificationTests.ReleasedTransferIntent...` creates the weak reference from a newly boxed transfer value after the blit; that object is disconnected from production retention. `GPU/FramebufferRoutingDsaTests.NamedRestorationProducesEquivalentResults` executes the same named route twice rather than comparing named and fallback routes.
- `GPU/GpuRenderBoundaryTests.BlitPreservesTargetAndCallerRouting(bool wrapped)` ignores `wrapped`, so its two discovered rows exercise the same owners. `GPU/GpuInitialTextureDependencyTests.UnavailableBackingPreventsInitialPublication` never reads the authored unavailable backing and exercises existing reservation reuse instead.
- `GPU/GpuVaoIntegrationTests` and `GpuVboIntegrationTests` have deletion-named cases that inspect wrapper state without an independent native deletion query; many VBO size/capacity assertions likewise inspect wrapper metadata. `GpuTextureSamplerIntegrationTests.BindScope_RestoresPreviousTextureAndSampler` checks cache getters without querying native restored bindings.
- `GPU/GpuVertexSelectionAndMultiBindingTests.DoubleHelperConfiguresMultipleAttributes` and `GPU/GpuVertexWrapperMetadataTests.WrapperConfigurationUsesSelectedAddressing` vary a capability record but submit through named `GL.VertexArray*` operations; the current vertex-array creation and geometry backend also use named driver calls. Their direct/legacy-helper claims therefore lack an executed alternative-path witness. Retain the existing rows while narrowing names and summaries to the behavior observed; decide separately whether a supported alternative-path integration test is required.
- `GPU/GpuResourceMetadataAcquisitionTests.ContextRetirementRemovesRegistrationWithoutDeletingNativeObjects` checks registry retirement but does not query native survival. `GpuResourceMetadataPublicationTests.RejectedBufferAllocationPreservesMeasuredCapacity` checks a negative-size guard and managed capacity rather than measuring native capacity. `GpuResourceRetirementRegressionTests.FramebufferBackingDeletionPreservesBoundAndRetainedSemantics` inspects a registry/helper attachment graph, not native framebuffer attachments.
- `GPU/GpuResourceWrapperLifecycleTests` has deterministic registry name reuse on the same physical object/context, not driver allocator reuse or a second native context. Its redirected-deletion methods check aliases, cache and surviving sentinels without querying deleted names; their nested Harmony factory installs no patch, while global interception supplies the behavior.
- `GPU/GpuSupportLimitsTests` checks no-recapture counts only in Debug; Release error preservation cannot rule out valid native polling. `GpuSpecializedQueryIntegrationTests` verifies availability/nonnegative results after bounded polling, not elapsed-time accuracy. `GpuSemaphoreLifecycleTests` replaces every external-memory driver slot with authored state, so it is a controlled component contract rather than external payload interoperability.
- `GPU/GpuSynchronizationLifecycleTests` can leave real native query or conditional intervals active if assertions fail; deleting a query does not necessarily end its interval. Its reload/retirement case also has a native sync whose failure-path cleanup is absent. `GpuUniformRingBufferIntegrationTests` ends a frame and deselects its program only on the success path, and its readback helper changes pack alignment without restoring it. Several VAO/VBO detached-name tests similarly clean up only after assertions.
- `GPU/LumOnCombineFunctionalTests` begins with debug composite shader variants before the remaining combine-program cases. Its AO-named case asserts reflectivity invariance while AO is stubbed, not AO attenuation. `LumOnDebugFunctionalTests` has mode assertions that generally prove visible output or one color predicate, not a full numerical mapping or mixed validity-color correspondence.
- `GPU/LumOnUpsampleFunctionalTests.SpatialSigma_AffectsDenoising` asserts only nonnegative variances, and several gather, temporal and trace cases have positivity or ordering oracles that do not force the named parameter response. In `LumOnProbeAtlasTraceFunctionalTests.RayHit_ReturnsSceneColor`, surface and ambient fallback are the same cyan, so the color assertion cannot distinguish a hit. Exact method oracles are recorded in `GpuFieldCorrections-AM.txt`; two trace tint/falloff methods remain statically skipped.
- The ten `GPU/LumonScene*` files exercise authored shader pipelines and controlled CPU/GPU composition. Material population/convergence and runtime wiring use no-op/null GPU page-table writers; the pipeline smoke case uses a counting-only writer. Tile oracles sample nominated centers rather than full tiles; the mesh-card depth predicate excludes NaNs. The two layout cases query linked SPIR-V interfaces without numerical dispatch. These groups do not prove deployed world rendering or GPU page-table publication.
- `OpenGLInterceptionGenerator.Tests/GeneratorCompilation` retains unique temporary PE paths statically without an evident cleanup owner. `Unit/LumOn/WorldProbes/RuntimeProbeWorldNotificationTests` verifies test-support behavior rather than production world-probe behavior. Review fixture ownership and naming respectively.
- `Unit/Rendering/Contracts/ShaderRegistryTests.SourcesAndRegistryCoverEachOther` reads the built asset snapshot and checks it against registered fixture sources. It needs a separate packaged-asset boundary decision from the isolated declaration/settings/scalar rules in the same directory.
- Many inspected test bodies lack explicit Arrange/Act/Assert boundaries and explanations of non-obvious ordering. The later migration must make the scenario legible without adding comments that only restate calls.

## Inventory limits and migration handoff

The complete discovery snapshot and source-to-owner routing are recorded in `Phase1.DiscoveredCases.jsonl`, `Phase1.MigrationRouting.csv`, and `Phase1.SupportRouting.csv`. `Phase1.SupportOwnershipDecisions.md` records helper lifetimes and retained observations about unreferenced support. The findings above and method-level oracle corrections are migration review work, not permission to remove cases, alter traits, or infer that a headless test proves deployed appearance. Native IDs and current runner membership remain the baseline for later moves.
