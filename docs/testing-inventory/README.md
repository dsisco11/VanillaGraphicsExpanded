# Test discovery baseline

`Phase1.DiscoveredCases.jsonl` records the xUnit v3 Release discovery from all four test projects on 2026-11-06. It contains 6,566 rows: 6,118 from `VanillaGraphicsExpanded.Tests`, 35 from `OpenGLInterceptionGenerator.Tests`, 256 from `ShaderBuildTool.Tests`, and 157 from `ShaderContractGenerator.Tests`. This is a discovery baseline, not an execution result or a classification of test boundaries.

Each row records the project, class, method, display name, discovered traits, static skip reason, and current runner selection. Runtime capability skips can differ from discovery; the later execution comparison must account for them. For the main project, `unit`, `all`, and `diagnostic` follow `UnitTests.runsettings`, `AllTests.runsettings`, and `DiagnosticTests.runsettings`. The three auxiliary projects have an unfiltered `default` selection. Main-project counts are 2,164 unit-selection rows, 5,920 all-selection rows, and 198 diagnostic rows; 11 of its rows are skipped. `dotnet test --no-build --list-tests` with each main-project runsettings file independently returned those same three counts.

`nativeUniqueId` is the xUnit case ID and `vstestId` is the VSTest case GUID, captured together from each VSTest diagnostic case object without executing tests. All 6,566 values of each are unique within their projects. `caseKey` is SHA-256 over project, a null separator, and `nativeUniqueId`; refresh it with `tools/TestSuiteInventory/Normalize-CaseIdentity.ps1`. Five auxiliary theory groups contain 22 rows with identical truncated display names. Their `displayNameOccurrence` values are display ordinals, not identity: the xUnit JSON listing does not distinguish those occurrences. The native IDs and VSTest GUIDs are paired within their diagnostic objects, and decoded serialized xUnit theory arguments uniquely matched all 22 native IDs to current `InlineData` rows in `Phase1.DuplicateTheorySourceRows.txt`. Those source locators are also attached as `theorySourceLine` in the JSONL. Compare native-ID sets and row counts for migration; do not infer identity from truncated names or occurrence order.

Discovery used each Release test executable with `-list full/json -preEnumerateTheories`, then `dotnet vstest <dll> /ListTests /Diag:<log>` for native IDs. The VSTest `TestDiscovery.TestFound` and `TestDiscovery.Completed` diagnostic payloads contain `Id` and the `XunitTestCaseUniqueID` property. The main executable was `VanillaGraphicsExpanded.Tests/bin/Release/net10.0/VanillaGraphicsExpanded.Tests.exe`; the other three were their `bin/Release/net8.0` or `net10.0` counterparts. Each project's newest local `.cs`, `.csproj`, `.json`, or `.runsettings` file was older than its Release DLL at capture. This timestamp check does not establish freshness of referenced projects, generated inputs, or installed game assets. A source search also found 24 files containing test-attribute tokens outside `*Tests.cs`, chiefly partial test files; executable discovery includes their compiled cases.

`Phase1.SourceMethods.csv` records 3,595 attributed source methods in 837 files, including partial test files. Each runtime row maps to exactly one of these methods by project, class, and method. The source index captures declaration location and available XML summary text; it is not evidence that a method's claimed contract, dependencies, or assertions are valid. Refresh it with `tools/TestSuiteInventory/Generate-SourceIndex.ps1`. The script ignores `[Fact]` examples inside XML comments and collection-definition classes before the actual test class.

`Phase1.SupportSources.csv` indexes the other 272 C# files in these projects, including fixture, assertion, helper, and collection sources. Its type and state columns are search cues. `Phase1.SupportRouting.csv` assigns every source to a reviewed responsibility group using `Phase1.SupportGroups.txt`; `Phase1.SupportOwnershipDecisions.md` records owner and lifetime boundaries, cleanup risks, and retained unreferenced-support observations. Group routing does not certify every support algorithm.

`Phase1.SupportOwnership.csv` adds direct type-name references from attributed test files to those 272 sources. It is generated by `tools/TestSuiteInventory/Generate-SupportOwnership.ps1`. String matches can include comments or incidental references and miss reflection/transitive use, so this is a navigation aid rather than an ownership conclusion.

`RootGroups.csv`, `UnitGroups.csv`, `AuxiliaryGroups.csv`, `GpuGroups-NZ.csv`, and `GpuGroups-AM.csv` are keyed by `SourceKey` from the source index. Their combined 3,595 keys cover every discovered source method exactly once. All 279 GPU A–M files and their 1,257 methods received source-body review, with profile exceptions and narrowed oracles recorded in `GpuOverrides-AM.txt`, `GpuFieldCorrections-AM.txt`, and `Phase1.BoundaryDecisions.md`. A method without an XML summary uses its method name as a contract label; the actual boundary and oracle fields, not that label alone, govern classification. `Phase1.MigrationRouting.csv` joins all 3,595 methods to current paths, proposed owners, levels, purpose, environment, uncertainty and 6,566 runtime-case counts. It flags current files with multiple levels or proposed owners so later batches can split them deliberately. These are routing decisions, not destination paths or permission to change selection.

To reproduce the main selection counts, run `dotnet test VanillaGraphicsExpanded.Tests/VanillaGraphicsExpanded.Tests.csproj -c Release --no-build --list-tests --settings VanillaGraphicsExpanded.Tests/<selection>.runsettings`, replacing `<selection>` with `UnitTests`, `AllTests`, or `DiagnosticTests`. To refresh case details, run each Release test executable with `-list full/json -preEnumerateTheories`, capture VSTest diagnostic discovery from its DLL, and regenerate the JSONL from both outputs. Rebuild first if project or referenced inputs have changed.
